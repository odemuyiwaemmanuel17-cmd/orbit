# Plan: Enable a satellite operator to visualize and track live-orbiting satellites in an immersive 3D Earth scene with accurate telemetry so orbital behavior becomes intuitive and verifiable.

**Complexity:** Large — new subsystem spanning two services (FastAPI propagation backend + R3F frontend); API contract must be stable before integration.

## Goal

Enable operators and enthusiasts to explore real satellite orbits around a textured 3D Earth with live telemetry and time-warp controls so that orbital mechanics become visually intuitive and quantitatively verifiable.

## Deliverables

**Backend (`backend/`)**
- API endpoint: `GET /api/satellites` → catalog of tracked satellites (id, name, group, NORAD ID, TLE lines) sourced from CelesTrak with an embedded fallback TLE dataset → gives the frontend a stable catalog contract.
- API endpoint: `GET /api/satellites/positions?timestamp=<ISO>` → per-satellite lat/lon/alt (km), velocity (km/s), ECI position → drives live satellite placement and telemetry HUD.
- API endpoint: `GET /api/satellites/{id}/orbit?minutes=90&steps=180` → projected ground/orbit trajectory points for the orbit polyline.
- Propagation core: `sgp4`-based pure-computation module (deterministic, offline-testable), with CelesTrak TLE refresh + TTL cache; CORS middleware for Vite dev server.
- `requirements.txt` pinning fastapi, uvicorn, sgp4, skyfield (optional accel path), httpx, pytest.

**Frontend (`frontend/`)**
- `src/components/Earth.jsx`: textured globe (day + night-lights + specular water layers via CDN textures with procedural fallback), custom Fresnel atmosphere shader shell, sun directional light.
- `src/components/SatelliteScene.jsx`: R3F canvas, InstancedMesh satellite rendering, glowing orbit Line geometries per selected satellite, OrbitControls (damped, zoom-constrained), Focus Mode camera lerp toward selected satellite.
- `src/components/Sidebar.jsx`: filterable satellite catalog grouped by type (stations / navigation / starlink / science); click selects and locks camera.
- `src/components/TelemetryHUD.jsx`: live lat/lon/alt, velocity, inclination, orbit-line toggle.
- `src/components/TopBar.jsx`: UTC clock, active satellite count, FPS counter, time-warp controls (1x/10x/60x + slider).
- Toast/status alert system for target switch and TLE refresh; API client with polling + graceful degraded mode when backend is offline (uses embedded snapshot data).
- Vite + Tailwind config with aerospace dark theme tokens; `/api` proxy to backend.

**Out of scope:** Ground stations, debris catalogs, user accounts/persistence, mobile-specific UX, real deployment infra (Docker/CI).

## Acceptance Criteria

```
AC-1  [Happy path]     Given the backend is running with the fallback TLE set, When GET /api/satellites is called, Then it returns ≥ 5 satellites each with name, group, and valid two-line element strings.
AC-2  [Happy path]     Given a valid satellite id, When GET /api/satellites/positions?timestamp=<now ISO> is called, Then each satellite has finite latitude (−90..90), longitude (−180..180), altitude > 160 km, and velocity > 6 km/s for LEO objects.
AC-3  [Happy path]     Given the frontend dev/prod build, When the app loads, Then the 3D canvas renders the Earth with atmosphere, satellites appear as instanced points on orbit rings, and the HUD shows live telemetry for the selected satellite.
AC-4  [Error path]     Given the backend is unreachable, When the frontend polls, Then the app degrades gracefully: status toast shown and last-known catalog snapshot is used instead of crashing.
AC-5  [Edge case]      Given a timestamp far in the future (+90 min), When the orbit endpoint is requested, Then exactly `steps` ECI points are returned forming a continuous trajectory of the orbit period or window.
AC-6  [Non-functional] Propagation of one epoch for the full catalog completes < 50 ms server-side (sgp4), and the frontend build succeeds with zero Vite errors.
```

## Implementation Path

1. **Backend core** — `backend/` package: TLE catalog loader (CelesTrak + fallback), sgp4 propagation module (`propagation.py`), FastAPI app (`main.py`) with the three endpoints; `requirements.txt`.
2. **Backend tests** — pytest covering AC-1, AC-2, AC-5, plus known-good ISS TLE regression values (verifiable without network).
3. **Frontend scaffold** — Vite React app, Tailwind, deps (`three`, `@react-three/fiber`, `@react-three/drei`, `lucide-react`), API client + store (polling, time-warp simulation clock).
4. **3D scene** — Earth.jsx (textures + Fresnel atmosphere), SatelliteScene.jsx (instanced satellites, orbit lines, focus camera).
5. **HUD** — TopBar, Sidebar, TelemetryHUD, toasts, theme polish.
6. **Verify** — run backend pytest; `vite build` the frontend; integration smoke: uvicorn up + curl endpoints, preview server fetch.
7. **Docs** — root README with run instructions.

## Assumptions

- CelesTrak may be unreachable at runtime → embedded fallback TLEs keep the app "ready to run immediately".
- Earth textures loaded from a CDN at runtime; procedural material fallback if offline.
- skyfield is listed as optional acceleration; the tested deterministic path uses pure `sgp4` (no JPL kernel download needed).
