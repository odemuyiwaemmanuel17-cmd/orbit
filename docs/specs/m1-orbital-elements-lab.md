# Plan: Enable learners to bend a mathematically generated orbit with the six classical elements and read the physics live, so that OrbitalPulse demonstrates genuine orbital-mechanics understanding without touching the approved tracker.

**Complexity:** Medium — new shared services (constants, Kepler math) with multiple consumers (lab UI, scene, tests); interfaces must be stable before the 21 later milestones build on them.

## Goal

Enable users to explore classical orbital elements interactively so that orbit geometry is generated from equations, verified by physics tests, and documented — extending, never altering, the ISS reference pipeline.

## Deliverables

- Constants module: `frontend/src/lib/constants.js` — μ_E, R_eq (6378.137 WGS84), R_mean (6371.0), J2 (1.08262668e-3), ω_E (7.2921159e-5 rad/s), g0, c, solar constant 1361 W/m², Ω_sun-sync ref, deg/rad helpers — each with units + source comment.
- Kepler service: `frontend/src/lib/kepler.js` — `elementsToState` (classical → ECI km + km/s), `stateToElements` (round-trip), `conicRadiusKm`, `solveKeplerEquation` (Newton, documented tolerance/iterations), `meanToTrueAnomaly`, `orbitPolylineEcI` (N samples over ν), `periodSec/velocityKmS/specificEnergy/angularMomentum/eccentricityVector`, node/perigee/apogee geometry helpers.
- Orbital Elements Lab: route `/lab/elements` (lazy, from tracker top bar button) rendering the existing OrbitScene with a `lab` prop; `LabOrbit` scene component drawing the analytical orbit via elementsToState → ECI → GMST → geodeticToScene (same projection contract as real sats), with perigee/apogee markers, ascending/descending node markers, orbital-plane fill toggle, optional equatorial-plane toggle, spacecraft marker animated by Kepler's equation on the engine clock.
- Lab panel (existing glass/mono styling): six engineering inputs with units (a_km, e, i_deg, RAAN_deg, argPerigee_deg, trueAnomaly_deg), ν play/pause + rate, "SHOW CALCULATION" equation inspector (r(ν), T=2π√(a³/μ), v=√(μ(2/r−1/a))), educational blurbs toggle, fidelity badge `ANALYTICAL MODEL — two-body`, engineering readout (r, v, energy, h, e-vector).
- Validation architecture: vitest configured (`npm test`), `frontend/tests/kepler.test.js` + `constants.test.js` — circular velocity 400 km → 7.6686 km/s, T(6778.137 km) → 5560.6 s (Kepler III), escape parity e=1 edge, i=0 planarity, node longitude at Ω, elem↔state round-trip, Kepler solver at e=0.9; `docs/VALIDATION.md` table (equation | reference | expected | result | Δ).
- Docs: ORBITAL_MATH.md Kepler section, ARCHITECTURE.md lab + constants section, ROADMAP.md 22-milestone platform table, PROGRESS.md entry.

**Out of scope:** TRACK/ANALYZE/DESIGN nav restructure (comes with its first consumers), backend endpoints for lab math (deliberately frontend — interactive, cached), landing page edits, attitude/propulsion modules (M11+).

## Acceptance Criteria

```
AC-1 [Happy]   Given lab sliders, when a/e/i/Ω/ω/ν change, the drawn orbit is recomputed from elementsToState (no decorative scaling): doubling a doubles apoapsis+periapsis radii analytically; markers move to computed positions.
AC-2 [Happy]   The spacecraft marker's ECI state equals elementsToState at the same ν within 1e-9 km; with playback on, ν(t) advances through Kepler's equation (faster near perigee — provable by equal-area sweep test).
AC-3 [Error]   Inputs are clamped to physical ranges (e ∈ [0, 0.95) for ellipse drawing, a > R_eq + 100 km); invalid combos show disabled state, never NaN geometry.
AC-4 [Edge]    i=0 renders equatorial orbit correctly (node markers hidden with honest "undefined for equatorial orbit" note); e→0 hides peri/apo markers duplicates gracefully.
AC-5 [Non-func] Existing /tracker behavior and landing unchanged: engine tick cost with lab closed is identical; lab module lazy-loaded (separate chunk); vitest + 48 pytest + vite build all green.
```

## Assumptions

- Lab uses two-body analytic mechanics (SGP4 TLE perturbations irrelevant for a teaching sandbox); Earth rotation handled by using real GMST per frame — orbit is inertial, Earth spins under it (physically honest).
- Scene radial compression (altToRadius) applies as documented for the tracker; angles/geometry faithful, radial distances log-compressed (VALIDATION.md notes this is display-space only; all reported numbers are in SI units, not scene units).
- "TypeScript checks" from the brief are N/A: repo is JS (TS migration documented as deferred); vitest + eslint-level strictness used instead.
