# Plan: Enable the tracker to display and interact with full constellations (test → GPS → NOAA → Starlink) so that thousands of real satellites render and propagate without slowing the scene or duplicating orbital logic.

**Complexity:** Medium — new engine subsystem + scene rendering path + backend data surface; interface must be stable before phased rollout.

## Goal

Enable the OrbitalPulse mission tracker to scale the validated ISS single-satellite pipeline to full constellations so that adding satellites never changes orbital math, degrades 60 fps rendering, or breaks the protected UI.

## Deliverables

- Pure module `frontend/src/lib/constellation.js`: `ConstellationGroup` — typed-array state (lat/lon/alt/scene xyz), staggered slice scheduler, injected projector, same satellite.js SGP4 call path as the ISS pipeline → single orbital logic for all groups.
- Engine extension (`engine.js`): `toggleConstellation(key)`, `_lookupEntry(id)` spanning featured + constellation records, promoted selected-constellation satellite into the exact full-accuracy snapshot entry path (telemetry, footprint, ground track, passes, orbit line unchanged), conjunction screening budget cap.
- Scene component `ConstellationField.jsx`: one `InstancedMesh` per active constellation, matrix updates in `useFrame` straight from typed arrays (zero React churn), selected member hidden from the field (rendered by the promoted full pipeline).
- Data tool `backend/tools/fetch_constellations.py` + seed files `frontend/src/data/constellations/{test,gps,noaa,starlink}.json` with live CelesTrak TLEs (phased caps: test 8 → gps 31 → noaa full → starlink subset → starlink large).
- Backend API mirroring the provider: `GET /api/constellations`, `GET /api/constellations/{key}` reusing `parse_tle_file`/`tle_to_satrec` with per-group TTL cache → same TLE provider, not a parallel one.
- CatalogPanel constellation chip row (existing chip styling) toggling groups and merging members into the searchable list (render cap with honest "narrow search" hint); `?debug` shows per-group count + avg slice cost.
- Node benchmark `frontend/tools/bench-constellation.mjs`: parse cost, full-sweep cost, slice cost at each phase cap — gate before raising satellite count.
- Tests: backend pytest for endpoints/cache/caps/404; node scheduler invariant test (every satellite refreshed within `divisor` ticks; selected excluded from slices).

**Out of scope:** UI redesign (absolute rule), WebSocket telemetry, per-constellation orbit rings, full catalog conjunction screening beyond budget cap, Iridium/oneWebSailor groups.

## Acceptance Criteria

```
AC-1  [Happy]      Given the ISS pipeline, when constellation group G is enabled, then G's satellites render as instances and their positions come from the same SGP4→geodetic→scene path as featured satellites (no separate orbital code).
AC-2  [Happy]      Given a constellation member is selected, then it appears in the snapshot with full telemetry, footprint, ground track, orbit line, and 10 Hz updates — identical to ISS behavior.
AC-3  [Perf gate]  Given group size n, unselected satellites are updated via time-sliced batches (~1 Hz per sat for n ≤ 300, adaptive cap beyond), and measured slice cost at every phase cap is < 25 ms in the node benchmark.
AC-4  [Edge]       A satellite id resolves in featured catalog first; enabling/disabling groups, scrubbing, and pausing never leaves stale typed-array positions for the selected satellite.
AC-5  [Error]      GET /api/constellations/{unknown} → 404; CelesTrak failure falls back to seeded/curated data with source labeled, never fabricated values.
AC-6  [Non-func]   Existing UI is visually untouched except additive chip row; unit tests and vite build pass; large group data loads lazily (code-split) and does not enlarge the initial bundle meaningfully.
```

## Implementation Path

1. **Interface lock** — `ConstellationGroup` API (activate/propagateSlice/tick scheduler/typed arrays) + data JSON schema shared by tool, engine, backend.
2. **Data** — write `fetch_constellations.py`, generate test (8) seed; verify TLEs parse.
3. **Engine + field** — registry, promotion path, instanced field, scene mount; wire test constellation end-to-end.
4. **Bench gate 1** — node benchmark at 8 + scheduler invariant.
5. **GPS (31)** → bench gate 2 → **NOAA** → bench gate 3 → **Starlink subset (~120)** → bench gate 4 → **Starlink large (cap by evidence)** → final gate.
6. **Backend mirror** — endpoints + cache + pytest.
7. **UI chips + diagnostics**; **docs** (ARCHITECTURE addendum, ROADMAP, PROGRESS).
8. Self-review (code-review), full verification ladder, delivery.

## Assumptions

- "Test set" = 8 mixed-regime real satellites under key `test` (kept enabled-able, off by default).
- Large Starlink cap is evidence-driven from benchmarks; bundle stays lazy-loaded.
- Conjunction screening keeps covering featured + active members up to 250 records; count disclosed honestly in UI.
- Bundled TLEs age; refresh tool documented, SGP4 staleness warning already handled by epoch checks.
